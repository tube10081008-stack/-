# 2. 핵심 개발자와 그들이 연구·차용한 테크놀로지

각 프로젝트별로 (i) 인물, (ii) 그 인물이 **직접 저술한 연구**, (iii) 제품에 **차용한 외부 기술**을 분리해 정리한다.

---

## 2.1 Character.AI

### 핵심 인물

| 인물 | 역할 | 배경 |
|---|---|---|
| **Noam Shazeer** | 공동창업자·초대 CEO (2021–2024) | Google Brain. 2024년 8월 Google DeepMind 복귀, 이후 Gemini 공동 리드 |
| **Daniel De Freitas** | 공동창업자·President | Google Meena/LaMDA 리드 디자이너. 2024년 8월 Google DeepMind 복귀 |
| **Karandeep Anand** | CEO (2025– ) | ex-Meta 제품 총괄. 안전 규제 대응과 "롤플레잉 창작 플랫폼" 전환을 주도 |

### Shazeer/De Freitas가 저술한 연구 계보 (제품의 기술적 DNA)

| 연구 | 연도 | 페르소나 LLM에서의 의미 |
|---|---|---|
| *Attention Is All You Need* (Transformer) | 2017 | 전체 카테고리의 기반 |
| *Outrageously Large Neural Networks* (Sparsely-Gated MoE) | 2017 | 캐릭터별 특화 용량을 조건부로 활성화하는 발상의 원류 |
| *Adafactor* | 2018 | 메모리 효율 옵티마이저 — 소규모 팀의 반복 학습 속도 |
| *Mesh-TensorFlow* | 2018 | 모델 병렬 학습 |
| ***Fast Transformer Decoding: One Write-Head is All You Need* (MQA)** | 2019 | **KV 캐시를 수십 배 줄여 장시간 대화 서빙 단가를 낮춘 핵심** |
| *Talking-Heads Attention*, *GLU Variants* | 2020 | 어텐션/FFN 미세 개선 |
| *Towards a Human-like Open-Domain Chatbot* (Meena, De Freitas 1저자) | 2020 | SSA(Sensibleness & Specificity Average) — "사람 같음"을 지표화한 최초 시도 |
| *LaMDA: Language Models for Dialog Applications* | 2022 | 대화 전용 사전학습 + 안전/근거성 파인튜닝. Character.AI의 직접 전신 |

### 제품에 차용·구현한 기술

- **서빙 최적화 3종**: (1) MQA 기반 KV 캐시 축소, (2) **로컬(슬라이딩 윈도) 어텐션과 글로벌 어텐션 혼합**으로
  긴 롤플레이 히스토리를 저비용 유지, (3) **레이어 간 KV 캐시 공유**.
- **스테이트풀 캐싱 / 세션 고정(sticky session)**: 같은 대화를 같은 서버로 라우팅해 prefix KV를 재사용 — 캐시 적중률을 크게 끌어올린 것으로 공개.
- **int8 양자화 학습·추론**: 학습과 서빙을 동일 정밀도로 맞춰 양자화 손실 없이 단가 절감.
- **Prompt Poet** (오픈소스, 2024): 캐릭터 정의·페르소나·기억·안전 지침을 **템플릿 + 토큰 예산 트렁케이션**으로
  조립하는 프롬프트 오케스트레이션 라이브러리. 사실상 "컨텍스트 엔지니어링"의 산업적 원형.
- **Age assurance ML**: 대화 어휘·로그인 패턴·계정 메타데이터로 연령을 추정하고, 3rd-party(Persona)·안면/신분 검증으로
  에스컬레이션. 2025년 11월 미성년자 오픈엔디드 채팅 전면 차단의 집행 수단.

## 2.2 zeta (스캐터랩)

### 핵심 인물

| 인물 | 역할 | 비고 |
|---|---|---|
| **김종윤** | 공동창업자·CEO | "연애의 과학" → 이루다 → 제타로 이어지는 페르소나 제품 라인의 기획자 |
| **황성구** | CTO | 한국어 NLU 딥러닝 기반의 **지속 학습형 ML 시스템** 구축 담당 |
| ML Research 조직 | 3개 트랙 | **내러티브 트랙**(이야기 흐름·몰입), **브레인 트랙**(대화 모델 지능·성능), **플레이어 경험 트랙**(사용 마찰 감소) |

> 조직도 자체가 본 보고서의 결론을 예고한다: 페르소나 LLM에서 "모델 품질(브레인)"과 "서사 품질(내러티브)"이
> **분리된 연구 대상**으로 취급되고 있다.

### 연구·차용 기술

| 기술 | 내용 | 근거 |
|---|---|---|
| **Pingpong-1** | 자체 개발 소형 언어모델(sLM). 파트너사용 "소셜 AI 구축 솔루션"으로도 제공 | 2025년 11월 공개 |
| **DPO (Direct Preference Optimization)** | 유저의 **답변 재생성 / 직접 수정 / 대화 지속** 행동을 암묵적 선호쌍으로 변환해 학습 | 기술 블로그 "유저와 함께 만드는 LLM" 1편 |
| **GRPO 온라인 러닝** | 리워드 모델이 생성 답변을 실시간 평가. 페어쌍이 필요 없어 **다양한 유저 시그널을 광범위하게 흡수** | 동 2편 |
| **주간 모델 배포 사이클** | 매주 새 LLM을 프로덕션에 배포하는 폐루프 | ML팀 인터뷰 |
| RLHF / 리워드 모델링, 서빙 최적화, 학습 데이터 전처리 | 기술 블로그 다수 | blog.scatterlab.co.kr |
| 이루다 계열 유산 | 리트리벌 기반 → 생성 기반 전환, 한국어 일상대화 코퍼스 | 2021~2022 |

**요약**: Character.AI가 *서빙 효율*에 최적화된 반면, 제타는 **"유저 행동 = 보상 신호"라는 온라인 정렬 루프**에
조직 전체를 최적화했다. 일 150분이라는 체류시간은 이 루프의 산출물로 보는 것이 타당하다.

## 2.3 Talkie / Xingye (MiniMax)

### 핵심 인물

| 인물 | 역할 | 배경 |
|---|---|---|
| **闫俊杰 (Yan Junjie)** | 창업자·CEO | ex-SenseTime 부사장/연구 총괄. CVPR 계열 비전 연구 다수 |
| MiniMax 리서치 팀 | MiniMax-01 / M1 / M2 저자단 | 2026년 1월 홍콩 증시 상장 |

### 연구·차용 기술

| 기술 | 내용 | 페르소나 제품에서의 함의 |
|---|---|---|
| **Lightning Attention** (MiniMax-01, arXiv:2501.08313) | 선형 어텐션 + 소프트맥스 어텐션 **하이브리드**. 장거리는 선형, 국소는 정밀 | 수천 턴짜리 롤플레이 히스토리를 **원가 선형**으로 유지 |
| **MoE 아키텍처** | 총 456B / 토큰당 45.9B 활성 | 캐릭터·장르별 이질적 분포를 하나의 모델로 흡수 |
| **초장문 컨텍스트** | 네이티브 100만 토큰(M1), 학습 시 최대 400만 토큰급 | "요약 없는 기억"이라는 극단 전략 |
| **MiniMax-M1** (arXiv:2506.13585) | 테스트타임 컴퓨트 스케일링, RL 학습(CISPO 계열 정책 최적화) | 롤플레이의 "생각하고 답하기" |
| 음성·영상 스택 (Hailuo 등) | TTS/음성 클로닝, 영상 생성 | 캐릭터의 **멀티모달 신체화** |
| Talkie 제품 계층 | 페르소나 시스템 + 캐릭터 매칭 보이스 + 구조화된 롤플레이 | 텍스트 서사에 음성 연기를 결합 |

**요약**: MiniMax의 베팅은 명확하다 — **"기억 문제를 컨텍스트 길이로 푼다"**. 선형 어텐션으로 컨텍스트 단가를
낮춰 요약·검색 없이 전체 히스토리를 밀어 넣는 방향이다.

## 2.4 세 조직의 기술 전략 대조

| | zeta | Character.AI | MiniMax(Talkie) |
|---|---|---|---|
| 병목을 무엇으로 봤나 | **정렬(alignment)**: 무엇이 재미있는가 | **단가(serving cost)**: 어떻게 싸게 오래 | **용량(capacity)**: 어떻게 다 기억하나 |
| 대표 기술 | DPO/GRPO 온라인 러닝, Pingpong-1 | MQA·하이브리드 어텐션·스테이트풀 캐싱, Prompt Poet | Lightning Attention, MoE, 1M 컨텍스트 |
| 기억 전략 | 요약 + 프롬프트 조립 + 학습된 선호 | 프롬프트 템플릿 + 토큰 예산 관리(Prompt Poet) | 초장문 컨텍스트에 원문 유지 |
| 남은 공백 | 서사 구조의 명시적 모델링 부재 | 동일 + 안전 규제로 인한 코호트 축소 | 동일 + 검색 없는 장문의 주의 희석 |

**공통 공백**: 세 조직 모두 *기억*은 열심히 다루지만 **서사(narrative)를 1급 상태(state)로 모델링하지 않는다.**
캐릭터 카드·요약·롱컨텍스트는 모두 "과거를 얼마나 정확히 재현하는가"의 문제이지,
"이야기를 어디로 끌고 갈 것인가"의 문제가 아니다. 3장에서 볼 최신 논문들도 대부분 같은 축에 머물러 있다.
