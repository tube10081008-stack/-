# server — 런타임 생성판

## 왜 이게 필요한가

아티팩트로 배포한 정적 버전에는 치명적 결함이 있었다. 발행된 페이지는 CSP 때문에 외부 API를
부를 수 없어서 생성을 오프라인 뱅크로 옮겼고, 그 순간 **모든 발화에 대한 답을 미리 적어야 하는 구조**가
됐다. "안녕?"이 소네트를 부르길래 인사 의도를 하나 추가했는데, 그건 발화 수만큼 프롬프트를
늘리겠다는 뜻이다. 될 리가 없다.

이 서버는 그 구조를 뒤집는다. **손으로 쓰는 것은 셋뿐이다 — 문우 카드, 코퍼스, 계약.**
의도 목록도, 응답 뱅크도, 키워드 표도 없다.

## 한 턴의 흐름

| 단계 | 주체 | 내용 |
|---|---|---|
| ① 읽기 | 모델 (flash) | 독자의 발화를 읽고 **상태 신호**만 보고한다 — 판정을 내렸는가, 동의만 하는가, 저항하는가, 새고 있는가. 범주 분류가 아니라 관찰이다 |
| ② 정책 | **코드** | (δ, π)를 결정한다. 이건 모델에게 맡기지 않는다. 이 프로젝트의 논지이기 때문이다 |
| ③ 검색 | 임베딩 | `gemini-embedding-001` 코사인 유사도 + 정책 보정(NNI·δ·π·난이도). 키워드 매칭 없음 |
| ④ MIP | 코드 | 선행 span을 자르지 않고 확장 |
| ⑤ 쓰기 | 모델 (pro) | 문우 카드·독자 상태·(δ,π)·제시될 원문·문자수 예산을 받아 **프레임만** 쓴다 |
| ⑥ 검증 | **코드** | 계약 집행. 위반이면 예산을 조여 재생성, 두 번 실패하면 원문 단독 |

모델은 인용문 텍스트를 만들지 않는다. 인용은 span_id로 참조되고 서버가 코퍼스에서 렌더링한다.

## 실행

```bash
pip install fastapi uvicorn requests
GEMINI_API_KEY=... python3 server/app.py     # http://127.0.0.1:8000
```

첫 기동에서 span 임베딩을 계산해 `corpus/embeddings.json`에 캐시한다.

| 환경변수 | 기본값 |
|---|---|
| `GEMINI_API_KEY` | 필수 |
| `PILDAM_READ_MODEL` | `gemini-2.5-flash` |
| `PILDAM_WRITE_MODEL` | `gemini-3.1-pro-preview` |

## API

| 엔드포인트 | 내용 |
|---|---|
| `GET /api/rooms` | 방 목록 |
| `POST /api/open` | `{room, tau}` → 세션 생성 |
| `POST /api/turn` | `{session_id, text}` → 블록 · 계기 · 고지 · 폴백 |
| `POST /api/tau` | 관계 연령 조정 (정의감 호출 실험용) |

```
독자> 나 오늘 좀 우울해

      위로를 기대하셨다면 유감입니다. 다시 읽기로 돌아가겠습니다.

독자> 다아시 진짜 재수없지 않아?
문우> 그 판정은 자유입니다. 하지만 첫인상은 대개 대상을 바라보는 자기 자신에 관한
      정보이기도 합니다. 감정에 호소하는 대신 해명을 택한 그의 편지를 아래에 둡니다.

```

## 정적판(`../app/`)과의 관계

`app/`은 네트워크 없이 도는 오프라인 미리보기이며, 프레임이 미리 생성된 뱅크에서 나온다.
새로운 발화에 약하다. **제품의 기준은 이 서버다.**
