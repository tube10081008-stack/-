# 04. 시스템 아키텍처

## 4.1 핵심 결정: 인용은 생성되지 않고 참조된다

L1(비대칭 출처 원칙)을 확률이 아니라 **구조**로 보장한다.

> **모델은 인용문의 텍스트를 출력하지 않는다. 인용의 좌표(span_id)만 출력한다.**
> 텍스트는 서버가 코퍼스에서 가져와 렌더링한다.

이 한 줄이 다음을 동시에 해결한다.

| 문제 | 통상적 해법 | 필담의 해법 |
|---|---|---|
| 인용 환각 | 사후 검증·재시도 | **구조적으로 불가능** — 모델은 문자열을 만들지 않는다 |
| 인용 왜곡·윤문 | 프롬프트 지시 | 동일 — 모델의 손이 닿지 않는다 |
| 적확성 손실(L3) | 검수 | 코퍼스가 단일 진실 원천 |
| 저작인격권·사자명예훼손 위험 | 정책 필터 | 발화 자체가 출처에 고정 |
| 논문의 「모델 강등」 | 사후 비준 절차 | 강등이 아니라 **애초에 권한 없음** |

논문 6.4절의 모델 강등이 사후 규칙이었다면, 필담에서는 **사전 권한 박탈**이다. 계승의 강화다.

## 4.2 응답 파이프라인

```
사용자 입력
   │
   ├─▶ ① 독서 상태 갱신     S_t = (진도, 미해결 질문, 표명 입장, 긴장, 밑줄 이력)
   │
   ├─▶ ② 컨트롤러           π_ϕ(δ_t, π_t | S_t, τ, 최근 신호)      ← 계층 III
   │
   ├─▶ ③ 검색               (δ, π) 조건부 span 검색
   │                        · δ 높음 → 독자의 밑줄·과거 발언 우선
   │                        · π 높음 → 독자의 표명 입장과 충돌하는 관점의 span 우선
   │
   ├─▶ ④ MIP 판정           요구된 감정 소득에 대해 필요한 최소 연속 분량 산출
   │                        → span을 자르지 않고 확장한다 (축소는 금지)
   │
   ├─▶ ⑤ 문우 프레임 생성    모델은 [span_id 목록 + 프레임 텍스트]만 출력
   │                        문우 코어(문체 지문·공리·금지 발화·모순 카드)로 조건화
   │
   ├─▶ ⑥ 계약 검증          VQR 하한 / 금칙 문체 / 프레임 예산 / span 존재 여부
   │                        위반 시 재생성 (최대 2회, 이후 인용 단독 폴백)
   │
   └─▶ ⑦ 렌더링             서버가 코퍼스에서 원문·번역·원어 병기를 materialize
```

### 실패 시 폴백이 대화가 아니라 인용이라는 점

⑥에서 두 번 실패하면 필담은 사과 메시지를 보내지 않는다. **원문만 보낸다.**
말할 것이 없을 때 침묵하고 원문을 내미는 것이 이 제품의 기본 예의이고, 최악의 응답조차
L1을 위반하지 않게 만드는 안전판이다.

## 4.3 코퍼스: MIP 인식 분절

고정 토큰 청킹은 이 제품에서 금지된다. 문장을 토큰 경계로 자르는 순간 적확성이 파괴되기 때문이다.

**분절 단위 = 호흡 단위(span).** 대사 한 덩어리, 문단, 시행 묶음처럼 **자르면 소득이 사라지는 최소 덩어리**.

각 span의 메타데이터:

| 필드 | 내용 | 용도 |
|---|---|---|
| `span_id` | 작품·판본·위치 결정적 식별자 | 인용 참조 |
| `work_id` / `locus` | 작품, 막·장·행 | 출처 표기 |
| `text_src` / `text_ko` | 원어 원문 / 자체 번역 | 병기 렌더링 |
| `translator_id` / `decision_log` | 번역자, 번역 결정 이력 | L3 감사, 적확성 대조 소재 |
| `mip_class` | 이 span이 단독으로 성립하는가, 선행 span을 요구하는가 | ④ MIP 판정 |
| `income_tags` | 이 대목이 생산하는 감정적 소득 유형 | 검색 |
| `viewpoint` | 누구의 시선인가 | **π 제어의 핵심 필드** |
| `difficulty` | 어휘·구문·배경지식 부하 | 입문 국면 보호 |
| `prereq_spans` | 스포일러·이해 선행 요건 | 진도 제어 |
| `wildness_note` | 이 대목의 결점과 그것을 압도하는 장점 | 적확성 대조·모순 카드 |

`viewpoint` 필드가 π 제어를 가능하게 하는 물리적 근거다. 독자가 "안나는 무책임하다"고 표명하면,
컨트롤러는 `viewpoint = 안나` 이면서 `income_tags`에 자기기만·사회적 압력이 붙은 span을 검색한다.
π는 프롬프트의 어조가 아니라 **검색 조건**이다.

## 4.4 금칙 문체 — 미끄러움의 기계적 차단

모델이 저작하는 프레임 텍스트에 다음을 금지한다. 문체 비평기(소형 분류기 + 규칙)가 판정한다.

| 금칙 | 예시 | 이유 |
|---|---|---|
| 감정 미러링 | "정말 슬프시겠어요", "그 마음 충분히 이해해요" | 정서적 공감 루프 — 인지적 소득 0 |
| 작품 평가 형용사 | "아름다운 문장이죠", "위대한 작품입니다" | 적확성은 지시되는 것이 아니라 겪는 것 |
| 요약 접속 | "요컨대", "정리하자면", "한마디로" | L2 위반의 언어적 표지 |
| 출처 없는 내면 서술 | "저는 그때 두려웠습니다" | L4 위반 — 지어낸 내밀함 |
| 사후 지식 | 저자 몰년 이후의 사건·개념 | 문우 코어 금지 발화 |
| 무해한 균형 | "물론 반대 의견도 있습니다만…" | π를 스스로 0으로 되돌리는 문장 |

마지막 항목이 특히 중요하다. 안전하게 양쪽을 다 인정하는 문장은 가장 미끄러운 문장이며,
정의감 호출을 무력화한다.

## 4.5 두 개의 시그니처 기능

### 적확성 대조 (Felicity Contrast)

문우가 **자신의 패러프레이즈를 원문 옆에 놓고** 독자에게 판정을 요구한다.

```
[좌] 원문 (+ 원어 병기)          [우] 모델이 다시 쓴 문장
        "어느 쪽이 더 정확합니까. 무엇이 사라졌습니까."
```

AI의 미끄러움을 숨기지 않고 교보재로 전시한다. 1.4절 오류 1(미끄러움을 문학으로 오인)에 대한
직접 대응이며, 부수적으로 **FEL 지표의 능동 측정 장치**가 된다.

### 정의감 호출 (Justice Appeal)

트리거: *R<sub>t</sub>* 에서 독자가 **빠르고 확신에 찬 도덕적 판정**을 표명하고, τ가 임계 이상이며,
해당 주제가 개인 안전 플래그에 걸리지 않을 때.

형식: 다아시의 문법을 따른다. 감정에 호소하지 않고 **정의감에 요구한다.**
그리고 반대 관점의 원문을 **자르지 않고** 제시한다. 요약은 이 기능에서 특히 금지된다.
관점을 요약하는 순간 그 관점은 반박하기 쉬운 허수아비가 되기 때문이다.

이 기능은 π의 최댓값을 쓰는 유일한 지점이므로, 05장에서 CES로 측정되고 07장에서 제약된다.

## 4.6 모델 구성

| 구성요소 | 역할 | 비고 |
|---|---|---|
| 문우 대화 모델 | 프레임 텍스트 + span 선택 | 한국어 문체 통제가 관건. 제타의 자체 sLM 전략(논문 3장) 계승 — 범용 최상위 모델은 문체 통제 비용이 크다 |
| 이중 언어 검색기 | 한국어 질의 ↔ 원어/번역 span | `viewpoint`·`income_tags` 조건부 검색 |
| 문체 비평기 | 금칙 문체 판정, SLP 산출 | 소형·저지연. 계약 검증 ⑥의 일부 |
| (δ, π) 컨트롤러 | 계층 III 정책 | 소형 정책망. GRPO |
| 리워드 모델 | 놀라움 대역·인지적 공감·잔존 연동 | 05장 지표로 학습 |

### 병목에 관한 메모

논문 3장은 세 운영사의 병목을 정렬(제타)·단가(Character.AI)·용량(MiniMax)으로 분류했다.
필담의 병목은 그중 어느 것도 아니다. **코퍼스 정합성**이다.
span 분절의 질, 번역의 적확성, 메타데이터의 정확성이 제품 품질의 상한을 결정하며,
이것은 GPU로 살 수 없고 사람이 만든다. 이 병목은 방어가 쉽다는 뜻이기도 하다.

## 4.7 데이터 모델 요약

```
Work ──< Span ──< Translation
                    └── DecisionLog

Reader ──< ReaderCore        (성장 주체, 계층 I-b)
       ──< ReadingState S_t  (계층 II)
       ──< Highlight         (FEL 원천)
       ──< StanceRecord      (R_t, CES 측정의 기준선)

Session ──< Turn ──< Block(quote | frame | appeal | contrast)
                      └── ProvenanceTag(원문 | 독자 | 모델)
                      └── Modality(캐논 | 가설 | 철회)
```

`ProvenanceTag`와 `Modality`는 논문 6.4절의 캐논 중재기를 그대로 옮긴 것이며,
필담에서는 스키마 수준의 필수 필드다. 태그 없는 블록은 저장되지 않는다.
